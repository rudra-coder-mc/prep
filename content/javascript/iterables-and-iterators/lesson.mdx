## Why this matters

`for...of`, spread, `Array.from`, destructuring an array, `Promise.all`, `new
Map(pairs)`, `yield*`. None of these know what an array is. They all speak one
protocol, and anything that implements it works with all of them. That is why
you can spread a `Map`, destructure a string, and `for...of` over a `NodeList`,
and it is why you cannot spread a plain object into an array.

Interviewers ask about it because it separates people who have used the
features from people who know why they work, and because "make this object
iterable" is a ten line task that shows whether you can read a spec-shaped
contract and implement it.

## Two objects, two methods

The protocol has two halves, and most confusion comes from conflating them.

An **iterable** is any object with a method under the well-known symbol
`Symbol.iterator`. Calling that method returns an iterator.

An **iterator** is any object with a `next()` method that returns
`{ value, done }`. Each call moves one step. When `done` is `true`, the
`value` is whatever the sequence finished with, usually `undefined`, and the
consumer stops.

The two roles are usually separate objects, the array and its iterator, but
the built-in iterators also implement `Symbol.iterator` by returning
themselves, so an iterator can be passed anywhere an iterable is expected. That
convenience is what makes `for (const x of map.keys())` work, and it has one
cost: an iterator is a one-shot sequence, so an iterator used as an iterable
can be looped exactly once.

## What is iterable

Built-in iterables: `Array`, `String`, `Map`, `Set`, typed arrays,
`arguments`, `NodeList` and the other DOM collections, and every generator
object. A string iterates by code point, not code unit, which is the one case
where `[...str]` and `str.split('')` disagree: an emoji is one element in the
first and two in the second.

**Plain objects are not iterable.** `for...of` over one throws `TypeError: obj
is not iterable`, and `[...obj]` throws the same. Object spread, `{ ...obj }`,
is a different feature that copies own enumerable properties and has nothing
to do with this protocol. To iterate an object, you choose what you mean:
`Object.keys`, `Object.values` or `Object.entries`, each of which returns a
real array.

That distinction is the answer to the `for...in` question. `for...in` walks
enumerable string keys, including inherited ones, and on an array it gives you
index strings plus whatever someone added to `Array.prototype`. `for...of`
walks the values an iterable produces. On an array they look similar; they are
doing different things, and `for...in` on an array is almost always a bug.

## Making one

An object becomes iterable the moment it has the method. The contract is small
enough to write from memory:

```js
class Range {
  constructor(from, to) {
    this.from = from
    this.to = to
  }
  [Symbol.iterator]() {
    let current = this.from
    const to = this.to
    return {
      next: () =>
        current <= to ? { value: current++, done: false } : { value: undefined, done: true },
    }
  }
}

;[...new Range(1, 3)] // [1, 2, 3]
for (const n of new Range(1, 3)) console.log(n) // 1, 2, 3
const [first, second] = new Range(10, 99) // 10, 11, and no further
```

Two things in that shape are not accidents. The state lives inside the
`Symbol.iterator` call, not on the instance, so every call starts a fresh
sequence and the range can be iterated twice. And `next` is an arrow function
so that if it is ever detached and called on its own, it still closes over
`current`.

The next topic shows that a generator writes the same thing in three lines.
Knowing the long form is what tells you what those three lines do.

## Stopping early

A consumer does not always read to the end. `break`, `return`, a thrown
error inside the loop body, and destructuring that takes two elements out of a
thousand all leave the sequence unfinished. For a range that is fine. For an
iterator holding a file handle, a database cursor or a lock, it is a leak.

So the protocol has an optional third method. If the iterator has `return()`,
every built-in consumer calls it on early exit, and only on early exit. When
the sequence finishes normally, `return()` is not called, because the iterator
already knows it is done.

```js
const iterator = {
  next() {
    /* ... */
  },
  return() {
    cursor.close()
    return { done: true, value: undefined }
  },
  [Symbol.iterator]() {
    return this
  },
}
```

`for...of`, spread, destructuring, `Array.from`, `Promise.all` and `yield*` all
honour `return()`. Calling `next()` by hand does not, which is the one place
cleanup is your responsibility. Generators implement `return()` for you,
running any `finally` blocks, which the next topic covers.

## The interview angle

> **"What makes something work with `for...of`?"**
> A `Symbol.iterator` method that returns an object with `next()` returning
> `{ value, done }`. Then name three built-ins that have it and the one
> common thing that does not: a plain object.

> **"`for...in` versus `for...of`?"**
> `for...in` walks enumerable property keys, including inherited ones, as
> strings. `for...of` walks an iterable's values. Use `for...in` for nothing
> you cannot do with `Object.keys`, and never on an array.

> **"Make this object iterable."**
> Write the method, keep the state inside it so the object can be iterated
> twice, and mention `return()` if the sequence holds a resource. Then say
> that a generator is the short way and write that too.

## Traps

- **`[...obj]` on a plain object throws.** Object spread in `{}` is a
  different feature. Use `Object.entries`.
- **An iterator is one-shot.** `const it = map.keys()` can be spread once;
  the second spread is empty. Spread the `Map` itself each time.
- **State on the instance instead of in the call** makes the object iterable
  exactly once. Put `current` inside `Symbol.iterator`.
- **`for...in` on an array** gives string indexes and picks up anything on
  `Array.prototype`.
- **`return()` is not called when `next()` is driven by hand,** so cleanup
  has to be explicit there.
- **`arguments` is iterable but not an array.** `[...arguments]` or rest
  parameters before calling any array method on it.
